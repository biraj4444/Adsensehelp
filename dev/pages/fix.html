CommonAdSense code not working

Problem

You added the script but AdSense cannot find it, or View Source does not show it.

Likely causes

  • The code is in the body, not the head.
  • The change was not deployed, or a cached page is served.
  • You edited a template the page does not use.
  • The snippet was retyped with a typo.

Fix

  1. Open the live page, choose View Source and search for adsbygoogle.js.
  2. If missing, add the exact snippet to the shared head template.
  3. Deploy, purge any CDN cache and reload in a private window.

Verify

One script tag inside the head with your real ID. The HTML checker shows all green.

CommonAds not appearing

Problem

The code is there but ad slots stay empty.

Likely causes

  • The site is not ready yet, or has account alerts.
  • Auto ads or the unit is not enabled, or the unit was never placed.
  • A new unit has not started serving yet.
  • An ad blocker is active in your browser.
  • The domain you test is not the one added in AdSense (for example localhost).

Fix

  1. Read your site status and alerts in AdSense.
  2. Confirm Auto ads or the ad unit is switched on and placed.
  3. Test in a private window with blockers off.
  4. Allow time. Never click your own ads to test.

Verify

The ins element gets a data-adsbygoogle-status attribute and there are no console errors. Use the live page inspector.

CommonWrong or placeholder publisher ID

Problem

Ads do not load, or AdSense flags ads.txt.

Likely causes

  • ca-pub-XXXXXXXXXXXXXXXX was never replaced.
  • A digit was dropped while retyping.
  • ads.txt uses ca-pub- instead of pub-.
  • An environment variable is missing in production.

Fix

Copy the ID from your account. HTML uses ca-pub- + 16 digits; ads.txt uses pub- + the same digits. Read it from one setting.

Verify

The same digits appear in View Source and in /ads.txt.

OftenCode placement problems

Problem

The snippet exists but sits in the wrong place or twice.

Likely causes

  • It is in the body or after </html>.
  • Several partials each add a copy.
  • Only some page templates include it.
  • The ad unit is inside a display:none element.

Fix

Move one copy into the shared head, delete the others and keep ad units in visible containers.

Verify

Exactly one script in the head on your home page, an article and a category page.

Commonads.txt problems

Problem

AdSense reports ads.txt as not found or invalid.

Likely causes

  • The file is not at the domain root.
  • The server returns an HTML page (a soft 404) or a login redirect.
  • Wrong ID or missing pub- prefix.
  • www and non-www serve different files.

Fix

Open https://yourdomain.com/ads.txt. It must show plain text with your line. Fix the cause, then wait for AdSense to re-crawl.

Verify

The ads.txt validator passes and the URL shows your line.

[[official]]

If the file displays in a browser, AdSense is likely to find it. Changes can take time. See the ads.txt troubleshooter.

[[/official]]
OftenVerification issues

Problem

AdSense cannot confirm that you own the site.

Likely causes

  • The code is not in the live HTML head yet.
  • You entered a different address (www or not) in AdSense.
  • The site is behind a password or firewall.
  • robots.txt blocks Mediapartners-Google.
  • A cache still serves the old page.

Fix

View Source on the exact address you entered, remove access barriers, check robots.txt and purge caches.

Verify

HTML checker and robots.txt checker are both clean.

SometimesAuto ads show nothing

Problem

Auto ads are on but nothing appears.

Likely causes

  • Auto ads are not enabled for this site.
  • The head script is missing on that page.
  • The page is very short.
  • A single-page app navigated without a reload.
  • A Content-Security-Policy blocks Google's scripts.

Fix

Confirm Auto ads are on, the script is in the HTML, then reload fully and wait. Adjust your CSP as Google's documentation describes.

Verify

No CSP or script errors in the console after a full reload.

OftenWorks in plain HTML, not in my framework

Problem

Your React, Next.js, Flask or Django app does not show the code or ads.

Likely causes

  • The script is added only by client-side JavaScript, so it is not in the first HTML.
  • React StrictMode runs effects twice.
  • NEXT_PUBLIC_ variables changed without a rebuild.
  • You edited a template the route does not use.

Fix

Put the script in the static head file or root layout, guard push with a ref, rebuild after changing build-time variables. See the React and Next.js examples.

Verify

View Source (not Inspect) shows the script and the console has no adsbygoogle errors.

OftenConsole: all ins elements already have ads

Problem

The console shows an error that all ins elements in the DOM already have ads in them.

Likely causes

  • push ran more times than there are empty units.
  • A component re-rendered and called push again.

Fix

Call push once per unit. In React use a ref guard, as in the Code Lab component.

Verify

The HTML checker shows push calls matching ad units, and the console error is gone.

OftenWorks locally, missing after deploy

Problem

Everything is right on your computer, but the live site lacks the code or ads.txt.

Likely causes

  • The host built an older commit.
  • ads.txt is not inside the published folder.
  • Environment variables are not set on the host.
  • The domain points at an old deployment.

Fix

Trigger a clean deploy of the latest commit, check the published folder contents and set variables in the host dashboard.

Verify

View Source and /ads.txt on the live domain match your latest files.

OftenHTTPS, DNS or redirect problems

Problem

Certificate warnings, redirect loops or the domain does not open.

Likely causes

  • DNS records point to an old server or have not spread yet.
  • The certificate is not issued yet.
  • Cloudflare SSL mode Flexible with an origin that forces HTTPS causes a loop.
  • Mixed content: an HTTPS page loads http:// files.

Fix

Check records for the root domain and www, wait for the certificate, use SSL mode Full (strict) when the origin has a valid certificate, and change http:// links to https://.

Verify

Both addresses open with a padlock and no loop.

SometimesOld version still showing (cache)

Problem

You changed the code or ads.txt but the live site looks the same.

Likely causes

  • The CDN or browser serves a cached copy.
  • Long cache times on HTML or ads.txt.
  • A script optimizer such as Cloudflare Rocket Loader delays the AdSense script.

Fix

Purge the CDN, hard-refresh or use a private window, keep HTML and ads.txt cache short, and exclude the AdSense script from optimizers (for Rocket Loader, add data-cfasync="false" to that script tag).

Verify

View Source on the live URL shows your latest code.

SometimesSite still reviewing or not ready

Problem

Everything looks right but AdSense has not approved the site.

What to know

Approval and timing are Google's decisions and nobody can guarantee them. Read every message in your account. Keep the code in place, keep the site online and improve content quality rather than changing the code.
